1        Introduction
In this paper, we consider deterministic data-structures in the Word-RAM model with w-bit words.
Supporting rank/select in Word-RAM is a widely studied problem [Jac88, CM96, Cla96, RRS07,
Gol07, GGG+ 07, Păt08, GORR09, GORR14, LLYZ23a, LZ25, KLZ26], especially for implementing
predecessor search [FW90, FW93, AMT99, AT07, PT14, CFHK15, NRL20].
    A fully indexable dictionary (FID) is a data-structure that encodes a bit-vector B ∈ {0, 1}u and
supports the following operations [RRS07, GGG+ 07, GRR08, GORR09, GORR14, NS14]:

 (1) rankb (B, x) = |{y ≤ x | B[y] = b}|, and

 (2) selectb (B, r) = min{0 ≤ x < u | rankb (B, x) = r} (−1 if empty).

A dynamic FID supports writes to B, that is, updating a bit at position i with value b (B[i] ← b).
Note that rank0 (B, i) = i + 1 − rank1 (B, i); from now on, we shall use rank interchangeably with
rank1 . In general, implementing select0 based on rank and select1 in the dynamic setting is
non-trivial, as it usually requires more space [GORR09, NS14, NN14]. See [RRS07, NS14] for
applications of select0 .1
     An equivalent description of a FID is to consider the set S = {0 ≤ x < u | B[x] = 1}. In this
view, a FID encodes a set S of n elements in [u] = {0, 1, · · · , u − 1}, supporting rank(S, x) =
|{y ∈ S | y ≤ x}| and select0 /select1 operations as before. A dynamic FID supports insertions
into S and deletions from S. Membership and predecessor queries to S can be answered by com-
puting select1 (S, rank(S, x)). For further details on predecessor data-structures, see the survey
of [NRL20].
     We focus on the density-sensitive case, where the data-structure knows both u and n = |S|
(i.e., the number of ones of B) [GORR09, GORR14]. We seek a FID that uses space close          to
the information-theoretic lower bound to encode B (equivalently S), which is given by lg nu bits.
For the running time, a lower bound is given in [FS89, PT14] and states that at least one of
rank1 /select1 /update must take Ω(logw (n)) time. The first deterministic dynamic structure with
worst-case O(logw (n)) time using O(nw) space is the dynamic fusion tree of [PT14].
     For dynamic memory allocation, we use the MB memory model [RR03, ADS16, LLYZ23a].
In this model, the space occupied by a dynamic data-structure equals the highest address in
memory that it uses. Dynamically maintaining space near lg nu is generally difficult in this
model [LLYZ23a]. Specifically, if two dynamic data-structures using s1 and s2 bits, respectively, are
concatenated, the resulting space may exceed s1 + s2 bits after multiple updates [LLYZ23a]. Stan-
dard techniques for concatenating dynamic memory segments [RR03, NN14, ADS16, LLYZ23a,
KLZ26] require either a fixed number of memory segments based on u [LLYZ23a], or a rebuild
whenever n changes significantly [KLZ26].
     Designing a space-efficient dynamic FID with O(logw n) worst-case time operations has been
a challenge. Apart from [PT14], most deterministic structures are either amortized, require large
precomputed tables, or rely on periodically rebuilding of static indices [NS14,
                                                                             NRL20, LLYZ23a,
Nav25]. Our main result is a deterministic dynamic FID that uses lg nu + O(nwϵ ) space (for
any constant ϵ < 1) and has worst-case O(logw n) time operations, while only using O(polylog w)
precomputed words. See Table 1 for a list of recent relevant results and the results presented in
this paper.

1.1     Contributions
In this section, we list our contributions and give an overview of our techniques. Recall that a
dynamic FID encodes a set S of n elements of [u] = {0, 1, · · · , u − 1} and supports rank/select
and updates. We employ the standard Word-RAM model with w-bit words and O(1) time mul-
tiplication, and use the MB memory model, expressing the space in bits. We assume w ≥ lg u.
All results use a precomputed table of polylog(w) words. A FID is said to have redundancy r if it
uses lg nu + r bits, for all u and n (the redundancy depends on u and n). All running times are
worst-case and all data-structures are deterministic. We prove the following theorem.
Theorem 1 (Dynamic FID). For every ϵ ≤ 1/2, there is a dynamic FID with O(nwϵ /ϵ) redundancy
that takes O(1/ϵ + logw (n)) time for rank/select0 /updates and O(logw (n)) time for select1 .

We divide the proof of this result into two parts: (1) reducing the problem to a small FID, and
(2) implementing a small FID by constructing separate data-structures for each operation.

2     Preliminaries
Terminology. For a FID, we only consider updates that add or remove an element from the set
S. For a sequence, updates that change its length are called indels: insertion of an element between
index i − 1 and i, so it becomes the new element at index i, and deletion of the element at index
i, so that the index i + 1 becomes the element at index i. A write to an entry of the sequence can
be implemented as a deletion followed by an insertion.

Notation. Let [u] = {0, · · · , u − 1}. Denote the size of a set S by |S|. We denote an ordered set
by {a0 < a1 < · · · < an−1 }. Denote by lg n ≜ ⌈log2 n⌉. We denote the concatenation of x and y
by juxtaposition xy and denote x repeated n times by xn . Our notation always writes the most-
significant bit first. For an array A, we denote the range A[i], A[i + 1], · · · , A[j] by A[i : j]. In a
tree, the degree of node ν, i.e., the number of children, is denoted deg(ν).

2.1    Computational model
We employ the Word-RAM model, where the memory is an array of 2w words of w-bits. Memory
reads and writes of a single word take O(1) time. We assume w ≥ lg u.

Instruction set. The standard AC0 operations2 of a w-bit word take O(1) time, namely addition,
bit-shifts (≪ and ≫), and bit-wise operations: AND (∧), OR (∨), XOR (⊕), and NOT (¬) [FW90,
FW93, AMT99]. We consider the “standard” Word-RAM model that has constant-time integer
multiplication [FW90, HMP01, PT14]. Other operations, such as most-significant bit (msb), least-
significant bit (lsb), Hamming-weight/popcount (wt), and integer division by a constant, can all
be implemented in terms of multiplication [FW90, GM94, PT14]. We note that operations can be
restricted to b bits by computing x 7→ x ∧ 0w−b 1b after every operation. In Section 6.1, we consider
other instruction sets.

2.1.1   Packed arrays
Often, we reinterpret a word as an array of k ≤ w/b blocks of b bits, which we call a k × b packed
array. We denote the i-th block by x[i | b] = x[i × b : i × b + b − 1]. When b is implied, we omit b
and write x[i].
     The usefulness of a packed array of O(w) bits resides in the fact that many array opera-
tions (which usually take linear time) can be implemented on it in O(1) time in standard Word-
RAM [FW90, FW93, PT14]. Namely, the following operations can be computed O(1) time:
(i) element-wise operations z[i | b] = x[i | b] ⋄ y[i | b] for ⋄ ∈ {+, ∧, ∨, ⊕}, (ii) broadcast operations
z[i | b] = x[i | b]⋄α for a constant α and ⋄ ∈ {≪, ≫, ×}, and (iii) parallel comparisons z[i | b] = 0b−1 1
iff x[i | b] ≤ y[i | b] and 0b otherwise. Some care is required for operations that can overflow (see
the proof of Lemma 8). Using lsb, we extend these to perform element search (find i such that
x[i | b] = e) and, if the elements are sorted, compute rank, all in O(1) time.
     We are also able to apply an operation to only a few entries if we have a mask for those
entries. For example, range indexing x[i : j | b] and comparison indexing x[i | b] where x[i | b] ≤ e.
Concretely, for a function q : [k] → {0, 1}, consider a conditional write, x[i | b] ← v[i | b] if q(i) = 1,
and x[i | b] ← x[i | b] otherwise. If we have the mask M [i | b] = q(i)b , the conditional write is
implemented by x ← (x ∧ ¬M ) ⊕ (v ∧ M ). More commonly, we have a mask M ′ [i | b] = 0b−1 q(i),
but it can be converted in O(1) time by M [i | b] = ¬(¬M ′ [i | b] + 1), or equivalently, M = M ′ × 1b .
     With these techniques, we support indels on a packed array in O(1) time. We cite the following
trick used in [PT14] to extend this idea to support indels for a small sequence.
Lemma 3 ([PT14]). For a sequence A of length k = O(w/ log w), we support indels into A in O(1)
time using O(k log w) additional bits.
Proof. We store A out of order, denoted A∗ , and a k × O(log w) packed array P such that A[i] =
A∗ [P [i]]. Note that P fits in O(1) words, thus indels in P are O(1) time. An insertion of x at position
i adds x to the end of A∗ and inserts its index at position i in P (i.e., P [i + 1 : k] ← P [i : k − 1] and
P [i] ← k). A deletion at position i moves the element A∗ [k − 1] to position P [i], updates at position
i∗ where P [i∗ ] = k−1 into P [i∗ ] ← i and deletes at position i in P (i.e., P [i : k−2] ← P [i+1 : k−1]).
Note i∗ can be found in O(1) time by element search.

2.2.1    Linear-space structures
In this section, we describe procedures for concatenating data-structures increasing the space by a
constant, which we call linear space. Here, a data-structure (an array, a FID, a dictionary, a tree,
etc.) has its own view of an array of cells in MB . We assume that the data-structure operations
allocate/de-allocate O(w) bits per operation.
    We present the following lemma to append a linear data-structure to an existing structure. This
lemma can be applied repeatedly to concatenate at most O(1) linear data-structures.

                                                        6
Lemma 5. Given a data-structure D1 that uses s1 bits and another data-structure D2 that uses s2
bits. Then, we can concatenate them to use s1 + O(s2 ) bits, increasing O(1) time for operations.

Proof. Re-parameterize so that D1 and D2 allocate/de-allocate at most w bits. We store D1 , then a
free space of O(s2 ) bits, then D2 , and at the end another space of O(s2 ) bits. In s2 /(2w) operations,
D1 and D2 have new sizes s′1 and s′2 , respectively. Because the sizes change by at most w bits per
operation, we have s1 − s2 /2 ≤ s′1 ≤ s1 + s2 /2 and s2 /2 ≤ s′2 ≤ 3s2 /2. We pad D2 with s2 /2 bits
to allow it to grow as needed. There is enough time to keep a copy of D2 in the free space and in
the end space. If the free space has more than 2s2 bits, we keep the free space copy and discard
the others, and if the free space has less than s2 /2 bits, we keep the end space copy. Note that the
concatenation allocates/de-allocates O(1) words for every word that each structure allocates.

    Lastly, we consider data-structures Dn with a parameter n, with operations that change n by at
most 1. We outline the standard trick to avoid rebuilding a data-structure when n changes. This
idea is also useful for de-amortization, especially for data-structures that have computed values that
strongly depend on n (e.g. Theorem 7). The idea is to allocate space for D2k for 0 ≤ k ≤ 2 + lg n.
The data-structure in use is stored in k = 1 + lg n. We keep a copy of the data-structure in each
k = 2 + lg n and k = lg n (only a partial copy of the smaller). If n doubles, we start allocating the
next power-of-two, and if n halves, we de-allocate the last one. We summarize with this observation.

Observation 1. Suppose that, for any parameter N , Dn uses O(N s) bits if n = Θ(N ). Then, we
can de-amortize Dn to use O(ns) bits for any n, adding O(1) time to the operations.


3     Cardinality reduction
In this section, we show a general procedure for reducing the FID problem to small sets. This is
often referred to as cardinality reduction (see [NRL20, §3.2] for details). The key idea is to use a
leaf-oriented tree [Die89, Wil00, AT07, BCC+ 18] where all leaves are at the same distance to the
root, and to employ auxiliary data-structures in the internal nodes to reduce the operations of rank
and select to a single leaf.

supporting the following operations.

for [PT14]. Thus, we are able to construct FIDs corresponding to these rank indices.

7    Conclusion and open problems
In this paper, we describe dynamic FID that use lg nu +O(nwϵ /ϵ) bits. Updates and rank/select0
                                                      

take O(1/ϵ + logw (n)) time, and select1 takes O(logw (n)) time. For ϵ = 1/4, this is the first
                                                                           √
deterministic dynamic FID in the standard Word-RAM model with o(n w) bits of redundancy,
optimal time for all operations, and worst-case times.
    With our generic reductions of Lemmas 1 and 2, further research may focus on building more
space-efficient rank indices. Alternatively, different constructions of small FIDs such as [KLZ26]
also fit into our framework, where we provide a general procedure to manage memory with worst-
case update times. We cite a few remaining open questions.

Lower bounds. The best lower bound is for the static case [PV10] that requires n/wO(t) re-
dundancy for O(t) time FID. A recent lower bound [LLYZ23b] holds for a polynomial universe
(u = n1+Θ(1) ) and w = Θ(log u), and states that any dynamic dictionary (that is, storing a dynamic
set and supporting membership) with O(n) redundancy requires Ω(log∗ (w)) time for membership,
where log∗ is the iterated logarithm. Considering Lemma 1, a time lower bound for a dynamic FID
of N = wO(1) elements and O(n) redundancy in the standard Word-RAM model is an interesting
open question.

Indices and dictionaries. Our results of Lemmas 2 and 6 have an additive term of O(n log w)
bits for the dynamic setting. These are the dominating terms for FIDs using the rank indices
of Theorem 3 and Corollaries 4 and 5. For polynomial universes, there are some results achieving
O(n) redundancy with ω(1) time select1 [PV17, PV20]. We leave for further work to improve
these results.
