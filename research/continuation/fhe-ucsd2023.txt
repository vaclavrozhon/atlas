           Lattice-based Encryption
●
    secret key: sk = s ∈Zⁿ
●
    Encₛ(m) = (A, As+mΔ+e) = (A,b)
    – A ← random matrix

    – e ← random noise (|e| < Δ/2)

●
    Decₛ(A,b):
    – c = (b – As) / Δ = m + e/Δ

    – output round(c) = m
             Additive Homomorphism
●
    C₀ = Encₛ(m₀) = (A₀, A₀s+m₀Δ+e₀)
●
    C₁ = Encₛ(m₁) = (A₁, A₁s+m₁Δ+e₁)
●
    C₀+C₁=((A₀+A₁),(A₀+A₁)s+(m₀+m₁)Δ+(e₀+e₁))
●
    If |eᵢ| < Δ/4, then
    – |e₀+e₁| < Δ/2

    – C₀+C₁ is a valid encryption of m₀+m₁

●
    ... but C₀+C₁+C₂ may not decrypt correctly
                Gentry bootstrapping
●
    Technique to reduce the amount of error in a lattice-
    based ciphertext:
    – Assume (Gen,Enc,Dec,Eval) supports the evaluation of
         fc(sk) = Decsk(c)
    – Publish ek=Enc(sk) as part of public key

    – Output c’ = Eval(fc,ek)

●
    Computing Dec homomorphically clears the noise of c
●
    Requires Enc to be “circularly secure”
Bootstrapping and Circular Security
●
    All known FHE schemes use bootstrapping
●
    Bootstrapping requires circular security
●
    Questions:
    – Can you transform any given FHE scheme into a new one
      FHE’ which is circular secure? ([..,AP16,GKW17,HK17]: no, at
      least for non-homomorphic encryption)
    – Can you prove circular security of FHE from standard LWE
      assumption?
●
    Still an open problem ...

                       CFHE implies FHE
●
    FHE: Dec(Eval(f,Enc(m))) = f(m)
●
    CFHE: Dec(Eval(f,c)) = f(Dec(c))
●
    Let c = Enc(m). Then
      Dec(Eval(f,Enc(m))
         = Dec(Eval(f,c))        [definition of c]
         = f(Dec(c))             [CFHE]
         = f(Dec(Enc(m))         [definition of c]
         = f(m)                  [correctness of decryption]

      CFHE without circular security?
●
    Question: Does FHE implies CFHE?
    – Given FHE scheme (Gen,Enc,Dec,Eval)

    – Build new CFHE scheme (Gen’,Enc’,Dec’,Eval’)

●
    Note: question does not involve circular security!
●
    Alternative 1: no such transformation is possible
    – give a black box separation between FHE and CFHE)

●
    Alternative 2: (FHE=>CFHE) => circular security
    – prove that any such transformation implies circular security

    Approximate Encryption (CKKS)
●
    Standard: Encₛ(m) = (A, As+mΔ+e)
●
    Approximate:
    – Encₛ(m) = (A, As+m+e)

    – Decₛ(A,b) = b – As = m+e ≈ m

●
    Removing Δ leads to substantial efficiency
    improvement due to slower error growth
Security of (Approx.) LWE encryption
●
    Regev 2005: Learning With Errors (LWE)
    – (A,As+e) ≈ (A,b) with b uniformly random

●
    Ciphertexts leak no information about m:
    – Encₛ(m) = (A, As+e+mΔ) ≈ (A,b)

    – Encₛ(m) = (A, As+e+m) ≈ (A,b)

●
    Is this enough to securely use LWE encryption?
        Insecurity of CKKS17 [LM21]
●
    Compute statistics on encrypted dataset x[1,..,n]
    – Enc(x[1]), Enc(x[2]), …. Enc(x[n])

    – Compute C = C[1]+C[2]+...+C[n]

    – Decrypt( C ) = x’ ≈ x = x[1]+x[2]+...+x[n]

●
    Assume the exact value of x becomes known
●
    Enough to recover the secret key sk from (x-x’) !
    – This is bad: it may allow to decrypt other, sensitive datasets

●
    Approximate FHE requires a new, stronger security definition
    than ciphertext indistinguishability [LM21,LMSS22]

    Approximate vs Exact Encryption
●
    Approximate encryption => Exact encryption
    – Dec(Enc(m)) = m+ε     for some |ε|<δ
    – Enc’(m) = Enc(2δm)

    – Dec’(c) = round(Dec(c)/(2δ))

●
    Question: can approximate FHE be more efficient than
    FHE ?
