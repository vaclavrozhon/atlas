                                         1 INTRODUCTION
                                         Subgraph listing is a crucial component of graph algorithms in many computation settings, as it characterizes the con-
                                         nections in a graph. In distributed computing, further motivation for ﬁnding small subgraphs is that some algorithms
                                         run faster on networks without certain subgraphs: [PS13, HRSS17] show fast algorithms for coloring and ﬁnding large
                                         cuts, respectively, in triangle-free graphs, and [CHFG+ 20] quickly computes exact girth in graphs without small cycles.
                                            In this paper, we focus on clique listing in the Congest model of distributed computing, in which 𝑛 vertices in a
                                         synchronous network are required to ﬁnd all cliques in the network graph by exchanging messages of 𝑂 (log 𝑛) bits.
                                            A major open question about the Congest model is whether randomization is necessary for this problem. A recent
                                         groundbreaking line of work [IL17, CPZ19, CS19, EFF+ 21, CHLL20, CHCLL21] culminated in clique-listing algorithms
                                         whose complexities are within polylogarithmic factors of the lower bounds presented by [PRS21, IL17, FGKO18]. While
                                         these are all randomized algorithms, powerful recent work by Chang and Saranurak [CS20] showed the ﬁrst non-trivial
                                         deterministic algorithm for the case of triangle listing. Still, it exceeds the lower bound by a polynomial number of
                                         rounds, leaving the following major question open (see also Open Problem 2.2 in a recent survey [CH21]):

                                              What is the complexity of deterministic clique listing in the Congest model, and is there a separation between
                                              randomized and deterministic algorithms?


                                            We present an algorithm answering this question for all 𝑝-cliques (denoted 𝐾𝑝 ). Our algorithm ﬁnishes in 𝑛 1−2/𝑝+𝑜 (1)
                                         rounds, within 𝑛𝑜 (1) rounds of the Ω̃(𝑛 1−2/𝑝 ) lower bound of [PRS21, IL17, FGKO18], and for listing cliques larger than
                                         triangles is the ﬁrst non-trivial deterministic algorithm. This complexity matches the optimal randomized results of
                                         [CPSZ21, CHCLL21], up to the additional 𝑛𝑜 (1) factor. The additional 𝑛𝑜 (1) factor is due to the deterministic expander
                                         routing scheme of [CS20], and might be improved upon given future progress in routing.

                                            Theorem 1. Given a constant 𝑝 ≥ 3 and a graph 𝐺 = (𝑉 , 𝐸) with 𝑛 = |𝑉 | vertices, there exists a deterministic Congest
                                         algorithm that completes in 𝑛 1−2/𝑝+𝑜 (1) rounds and lists all instances of 𝐾𝑝 in 𝐺.

    Our key technical contribution which enables showing Theorem 1 is a simulation in Congest of a class of algorithms
we call partial-pass streaming algorithms. We use these to eﬃciently simulate deterministic load balancing tools from
the stronger Congested Cliqe model (where every two vertices can exchange 𝑂 (log 𝑛)-bit messages per round). It is

1.1    Background and Challenges
The groundbreaking triangle listing result of Chang, Pettie, Saranurak, and Zhang [CPSZ21]1 consists of a distributed
expander decomposition, in which the graph is broken up into well-connected (high conductance / low mixing time)
clusters, and Congested Cliqe-inspired algorithms that run eﬃciently in each cluster using the expander routing
of [GKS17, GL18]. The remaining 𝜖-fraction of inter-cluster edges are handled recursively. This general framework has
become the foundation for further work in this area [EFF+ 21, CHLL20, CHCLL21, CS20, CHFG+ 20, ILM20, CHFL+ 22].
    Speciﬁcally, after running the expander decomposition, the 𝐾3 listing algorithm of [CPSZ21] runs a randomized
version of the triangle listing Congested Cliqe algorithm of Dolev, Lenzen, and Peled [DLP12]. For the case of
𝑝 ≥ 4, signiﬁcant new challenges arise as cliques of size 4 and larger can have their edges spread out over two or
more clusters in the decomposition. This implies that some edges need to be learned by a cluster although neither of
their endpoints is in the cluster, and thus the number of edges that a cluster has to process is much larger. The listing
algorithms of Eden, Fiat, Fischer, Kuhn, and Oshman [EFF+ 21], Censor-Hillel, Le Gall, and Leitersdorf [CHLL20], and
Censor-Hillel, Chang, Le Gall, and Leitersdorf [CHCLL21] use various techniques for resolving the above.

    Usage of randomization in previous approaches. Together, [CPSZ21, CHCLL21] show optimal randomized al-
gorithms for listing cliques of any size in Congest. On a conceptual level, randomization is used in three components
of the algorithms. The ﬁrst two are the expander decomposition and the expander routing. The third component that
uses randomization is the load balancing for the listing operation inside the clusters, upon which we now elaborate.
    The load balancing task is as follows. Each cluster knows some set of edges (distributed across the cluster vertices) —
only the cluster’s own edges for 𝐾3 , and for 𝐾𝑝 ≥4 perhaps also edges from other clusters. The goal is for the vertices to
redistribute these edges, such that any instance of 𝐾𝑝 composed of these edges is known to at least one vertex in the
cluster. This must happen without any vertex slowing down the network by sending or receiving too much information.
The standard approach is to construct a random partition of the vertex set 𝑉 = 𝑉1 ∪ 𝑉2 ∪ · · · ∪ 𝑉𝑥 , for 𝑥 = 𝑂 (𝑛 1/𝑝 ),
so that the number of edges between two parts 𝑉𝑖 , 𝑉 𝑗 is, with high probability, roughly |𝐸|/𝑥 2 . Then, each vertex 𝑣 is
assigned some parts 𝑉𝑖 and 𝑣 learns all edges between these parts. By assigning a number of parts proportional to the
degree of 𝑣, the near-optimal round complexity is obtained.

    Challenges in removing randomization. Chang and Saranurak [CS20] show deterministic expander decomposi-
tion and routing procedures. However, deterministically solving the above load balancing task is diﬃcult to do inside
the clusters, implying a polynomial overhead to their triangle listing round complexity.
    The challenge of ﬁnding an eﬃcient deterministic algorithm for the load balancing task arises not only in Con-
gest, but also in Congested Cliqe. Speciﬁcally, it is unknown how to eﬃciently ﬁnd in a deterministic manner
a well-balanced partition of the graph such that the number of edges between every two parts is roughly the same.
In Congested Cliqe, [CHLT20] bypassed this challenge for triangles, and [CHFG+ 20] were able to do so for any
subgraph (with at most log 𝑛 vertices). The approach of the latter is that instead of using one partition, they design a

polynomial number of partitions and diﬀerent vertices choose to work with diﬀerent combinations of partitions. The
diﬀerent partitions are related to each other using a structure called partition trees.
  A reasonable approach for deterministic load balancing in Congest for clique listing is to construct the above
partition trees inside the clusters. However, the above algorithm for constructing these trees cannot directly be adapted
to Congest in an eﬃcient manner. The reason for this is that the algorithm has low round complexity, yet high message
complexity: although it ﬁnishes in 𝑂 (1) rounds in the Congested Cliqe model, it involves sending Θ(𝑛 2 ) messages.
This high message complexity is very prohibitive for the Congest model, as the bandwidth available, i.e. the number
of communication edges in the graph or in a cluster, might be dramatically smaller than Θ(𝑛 2 ), as we now elaborate.
   When dealing with 𝐾3 , our target round complexity is 𝑂˜ (𝑛 1/3 ), as the known lower bound stated above is Ω̃(𝑛 1/3 ).
This implies a very hard restriction on the bandwidth available within the clusters. Concretely, it can be shown that
some low-degree vertices in the clusters can only receive 𝑂 (𝑛 2/3 ) messages in total throughout the entire algorithm.
Therefore, for clusters with Ω(𝑛 2/3 ) vertices, some vertices might not even know basic information about the other
cluster vertices, such as how much data each holds, and so performing any sort of load balancing is clearly tricky.
  When dealing with 𝐾𝑝 ≥4 , our target round complexity inherently increases, as the lower bound is Ω(𝑛 1−2/𝑝 ), which
is at least Ω(𝑛 1/2 ) for 𝑝 ≥ 4. While this eases the pressure on the bandwidth, we are met with a new challenge:
constructing partition trees on data from multiple clusters. As described above, a clique of size ≥ 4 can have edges
which lie in multiple clusters, and so as in [CHCLL21], we need to make some edges from outside a cluster known to the
vertices of the cluster. To capture this, we must substantially generalize the deﬁnition of partition trees to distinguish
between edges in the cluster and those whose information is brought into it.


1.2   Our Approach
We introduce a new class of algorithms which we call partial-pass streaming algorithms, and show that these require
very few messages to simulate in clusters in Congest. Then, we show that there exists a partial-pass streaming algo-
rithm which constructs a generalized partition tree. Finally, we plug this construction into the deterministic expander
decomposition and routing of [CS20] in order to get listing algorithms for all 𝐾𝑝 .


  Partial-pass streaming algorithms. Partial-pass streaming algorithms are similar to standard streaming algo-
rithms (see, for example, [MP80, AMS99] or the survey [Mut05]), as they maintain a small state, sequentially process
an input stream, and cannot return to previous parts of the input. However, a key distinctive part of partial-pass stream-
ing algorithms is that they strive to make less than one pass over the input stream by skipping some of it. In this setting,
a stream is composed by tokens reﬂecting two levels of granularity: a large number of auxiliary tokens, each with some
ﬁne-grained data, and a small number of main tokens with very coarse-grained data summarizing the auxiliary tokens.
Each main token summarizes the chunk of auxiliary tokens that appears after it and before the next main token in the
stream. Partial-pass streaming algorithms are able to access all the main tokens in a given stream, while reading only
a limited amount of auxiliary tokens. As such, the total number of stream tokens accessed by a partial-pass streaming
algorithm is signiﬁcantly smaller than the total stream length.
  As intuition for this deﬁnition and why it ﬁts well with a Congest simulation, recall that in Congest the input is
dispersed across vertices. The raw data each vertex gets can be seen as auxiliary tokens, and each vertex can locally
compute a summary of its data, creating a main token. When an algorithm runs, it might suﬃce to sometimes only
read the main token produced by a vertex, while at other occasions the internal auxiliary tokens are needed.

    Simulating partial-pass streaming algorithms in Congest. For simplicity, suppose each vertex has a single
main token which summarizes possibly many auxiliary tokens which it holds. Assume also that the vertices are ordered
in the way their tokens appear in the stream, i.e., vertex with identiﬁer 1 has the ﬁrst main token. The algorithm which
we run on the stream has a small polylog(𝑛)-bit state. Consider two extreme approaches.
    Approach 1: State Passing. Vertex 1 starts simulating the algorithm and locally executes it on its tokens. Then, it
passes the state of the algorithm to vertex 2 and so forth. While only Θ̃(𝑛) messages are used, this takes Θ̃(𝑛) rounds.
    Approach 2: Leader with Queries. An arbitrary vertex 𝑣 is denoted leader and learns all 𝑛 main tokens. Then, 𝑣 locally
simulates the algorithm. When auxiliary tokens of a certain main token are needed, 𝑣 sends the state of the algorithm
to the vertex 𝑢 which sent 𝑣 that speciﬁc main token. Vertex 𝑢 simulates the algorithm on its local auxiliary tokens and
sends the state back to 𝑣. As main tokens summarize the auxiliary tokens and partial-pass streaming algorithms are
able to skip the vast majority of auxiliary tokens, 𝑣 sends the state to other vertices only few times during the entire
execution. However, we are burdened by the fact that 𝑣 initially learns all 𝑛 main tokens by itself.
    Our approach. We opt for a combination of both approaches. Denote some set of vertices 𝐴 of sublinear polynomial
size, ordered 𝐴 = {𝑎 1, . . . , 𝑎 |𝐴 | }. The vertices in 𝐴 collectively learn all main tokens — 𝑎 1 learns the ﬁrst 𝑛/|𝐴| main
tokens tokens, followed by 𝑎 2 which learns the next 𝑛/|𝐴|, and so forth. Vertex 𝑎 1 starts executing the algorithm on its
local data. Whenever it hits a main token for which the corresponding auxiliary tokens are needed, it sends the state
of the algorithm back to whichever vertex sent it the relevant main token. That vertex simulates the algorithm, and
returns the state back to 𝑎 1 . After 𝑎 1 processes the main tokens it knows, it forwards the state of the algorithm to 𝑎 2 ,
and so forth, until 𝑎 |𝐴 | completes the run of the algorithm. This approach both passes the state few times and each
vertex learns few main tokens, thus having both low round and low message complexities.


    Constructing generalized partition trees by a partial-pass streaming algorithm. We design a partial-pass
streaming algorithm which constructs the generalized partition trees we require, so that we can then invoke our
simulation of it in Congest. For clarity, the following is a simpliﬁcation of the full algorithm which we show. At a very
high level, a common operation in constructing partition trees is that there is a globally known vertex set 𝑊 , and we
strive to partition the graph vertices 𝑉 into sets 𝑉1, . . . , 𝑉𝑥 , for some 𝑥, such that for each 𝑖, 𝑗 ∈ [𝑥], the number of edges
in 𝐸 (𝑉𝑖 ,𝑊 ) is roughly the same as that in 𝐸 (𝑉 𝑗 ,𝑊 ). We work within clusters and each cluster needs to process also
information that is brought from outside it. Concretely, denoting 𝑉𝐶 as the set of vertices in a cluster 𝐶, each 𝑣 ∈ 𝑉𝐶
might also hold some edges incident to vertices outside 𝐶, a set which we for now denotes as 𝐹 (𝑣) ⊆ 𝑉 \ 𝑉𝐶 .
    The partial-pass streaming algorithm works as follows. For each 𝑣 ∈ 𝑉𝐶 , deﬁne |𝐹 (𝑣)| + 1 auxiliary tokens as the
value |𝐸 ({𝑣 },𝑊 )| and values |𝐸 ({𝑢},𝑊 )| for each 𝑢 ∈ 𝐹 (𝑣). Also deﬁne a main token for 𝑣 as the sum of these auxiliary
tokens. The input stream is the concatenation of the tokens deﬁned for each 𝑣 ∈ 𝑉𝐶 . The algorithm maintains an
incomplete part 𝑉 𝑗 in the partition to which we currently add vertices. When reaching the main token of vertex 𝑣 ∈ 𝑉𝐶 ,
we attempt to add all of 𝐹 (𝑣) ∪ {𝑣 } to 𝑉 𝑗 . By observing the main token of 𝑣, we know how many edges will be added to
𝐸 (𝑉 𝑗 ,𝑊 ) if we do so. If this value is acceptable, the algorithm proceeds. Otherwise, we request all the auxiliary tokens
of 𝑣, and add the vertices one by one until 𝑉 𝑗 grows too large, at which point we close 𝑉 𝑗 and start ﬁlling part 𝑉 𝑗+1 .


    Roadmap. We provide required background in Section 2, and in Section 3 introduce and eﬃciently simulate partial-
pass streaming algorithms in high-conductance clusters in Congest. In Section 4, we construct partition trees using
partial-pass streaming algorithms. Sections 5 and 6 wrap these into 𝐾3 and 𝐾 ≥4 listing algorithms, respectively.

1.3   Further Related Work
Triangle ﬁnding. In Congested Cliqe, the seminal work of [DLP12] presents an 𝑂 (𝑛 1/3 /log 𝑛)-round, deterministic
algorithm for 𝐾3 listing, and shows faster algorithms for detection and counting for certain graph families. Matching
lower bounds for listing are shown in [PRS21, IL17]. For sparse graphs, [DLP12, PRS21, CHLT20] show faster algo-
rithms, some of which are tight due to [PRS21]. The state-of-the-art for triangle detection and counting in Congested
Cliqe is 𝑂 (𝑛 0.158 ) rounds, based on fast matrix multiplication [CHKK+ 16]. It is considered hard to show lower bounds
for this, due to the reduction to circuit complexity of [DKO14]. the broadcast version of Congested Cliqe.
   In Congest, the ﬁrst breakthrough for triangle ﬁnding is due to [IL17], who showed the ﬁrst non-trivial algorithms
for listing and detection, in 𝑂˜ (𝑛 3/4 ) and 𝑂˜ (𝑛 2/3 ) rounds w.h.p, respectively. Subsequently, [CPSZ21] showed a break-
through by listing in the optimal complexity of 𝑂˜ (𝑛 1/3 ) rounds, w.h.p., using an expander decomposition together with
the routing techniques of [GKS17, GL18]. [HPZZ21] show an algorithm which takes 𝑂 (Δ/log𝑛 + log log Δ) rounds,
where Δ is the maximal degree in the graph. following: Subsequently, [CPZ19] showed a breakthrough by listing in
𝑂˜ (𝑛 1/2 ) rounds, w.h.p., using an expander decomposition, which was later improved to get the optimal, yet random-
ized, 𝑂˜ (𝑛 1/3 )-round algorithm of [CS19]. The ﬁrst non-trivial deterministic triangle ﬁnding algorithm was given by
[CS20], taking 𝑂 (𝑛 0.58 ) rounds for detection and 𝑛 2/3+𝑜 (1) rounds for listing. On the lower bound side, it is only known
that more than one round is needed for detection in Congest [ACHKL20, FGKO18]. Proving any polynomial lower
bound is considered diﬃcult [EFF+ 21].
   Finding larger cliques. In Congested Cliqe, [DLP12] provide an 𝑂 (𝑛 1−2/𝑝 /log 𝑛)-round deterministic algorithm
for 𝐾𝑝 listing. Further, their algorithm lists all subgraphs with 𝑝 vertices within this complexity. This is optimal for
cliques due to the lower bound of [FGKO18]. A randomized sparsity aware algorithm was shown for 𝐾𝑝 listing, for
𝑝 ≥ 4, in [CHLL20], and a deterministic construction using partition trees was later given by [CHFG+ 20]; these results
are tight, for graphs of all sparsities, due to [PRS21, IL17, FGKO18].
   In Congest, the expander decompositions of [CPZ19, CS19] were ﬁrst used by [EFF+ 21] to show 𝐾4 and 𝐾5 listing
in 𝑛 5/6+𝑜 (1) and 𝑛 73/75+𝑜 (1) rounds w.h.p., respectively. Later, [CHLL20] showed the ﬁrst sub-linear result for all 𝑝 ≥ 4,
which was followed by the 𝑂˜ (𝑛 1−2/𝑝 )-round algorithm of [CHCLL21] — this is optimal due to the lower bound of
[FGKO18]. For 𝑝 = 4, it turns out that the optimal Θ̃(𝑛 1/2 )-round result for listing 𝐾4 is also the best possible for
detecting 𝐾4 , due to the lower bound by [CK20].
   Finding other subgraphs and additional related results. Small cycles received much attention with many al-
gorithms and hardness results, shown in Congested Cliqe by [CHKK+ 16, CHLT20, CHFG+ 20], and in Congest by
[DKO14, KR18, CHFG+ 20, FGKO18, EFF+ 21]. For all 𝑝 ≥ 3, a gap between 𝐾𝑝 detection and listing is shown in quantum
variants of Congest and Congested Cliqe in [ILM20, CHFL+ 22]. Finding trees was investigated in [DKO14, KR18],
and more general subgraphs in [GO18, FGKO18, EFF+ 21]. Distributed subgraph testing, in which we need to determine
if a graph is either free of a subgraph or many edges need to be removed from it to reach this state, was studied in
[BPS11, CHFSV18, EFF+ 17, FO19, FRST16].

3 SIMULATING PARTIAL-PASS STREAMING ALGORITHMS IN CONGEST
A partial-pass streaming algorithm for parameters 𝐿, 𝑁 in, 𝑁 out, 𝐵 aux, 𝐵 write is a procedure that satisﬁes the following.
There is an input stream 𝑆, which is a sequence of 𝑁 in main tokens, 𝑆 = h𝜏1, 𝜏2, . . . , 𝜏𝑁in i. Each main token 𝜏𝑖 has an
associated sequence of ℓ𝑖 auxiliary tokens, 𝛼𝑖 = h𝛼𝑖,1, 𝛼𝑖,2, . . . , 𝛼𝑖,ℓ𝑖 i The algorithm produces a write-only output stream
𝑅 = h𝜌 1, 𝜌 2, . . . , 𝜌 𝑁out i, by invoking operations that are either READ, GET-AUX, or WRITE, as follows. The operation READ
reads the next token from the input stream 𝑆; the operation GET-AUX adds the auxiliary tokens associated with the last-
read main token to the beginning of 𝑆, so that if the previous READ operation returned 𝜏𝑖 , the next ℓ𝑖 READ operations
will return the sequence 𝛼𝑖 ; and the operation WRITE writes a token to the end of the output stream 𝑅. The algorithm
may perform at most 𝐵 aux total GET-AUX operations. Additionally, the algorithm may perform at most 𝐵 write WRITE
operations between two (not necessarily consecutive) READ operations that read consecutive main tokens 𝜏𝑖 , 𝜏𝑖+1 . All
main, auxiliary, and output tokens are at most 𝐿 bits long. Apart from the write-only output stream 𝑅 for which 𝑁 out
may be large, the rest of the space used by the algorithm must be polynomial in 𝐿.
  The motivation for the restriction that a partial-pass streaming algorithm may access auxiliary tokens for at most
𝐵 aux main tokens is that the algorithms we wish to simulate use the main tokens as “summaries” of their corresponding
                                                                                                          Í
sequences of auxiliary tokens. These algorithms operate on extremely long sequences of input; that is, 1≤𝑖 ≤𝑁in ℓ𝑖 is
huge. We cannot aﬀord to move all of the auxiliary tokens around the cluster during a simulation in Congest; however,
most of the time, these algorithms can obtain all necessary information about the input from some summarizing
function that aggregates the information in many auxiliary tokens into just one main token. When the algorithm
ﬁnds that it in fact needs more granular information, it inspects each of the auxiliary tokens that correspond to the
summarizing main token. However, inspecting a sequence of auxiliary tokens remains an expensive component of the

simulation process, which is why we need to have a good bound 𝐵 aux on the number of times an algorithm may need
to access a stream of auxiliary tokens in order to guarantee a suitable round complexity.

3.1    The Simulation
We eﬃciently simulate partial-pass streaming algorithms when their input is distributed to the vertices of a commu-
nication cluster in a suitable manner. Speciﬁcally, we require that each vertex holds a small, contiguous part of the
input stream. We also require that the vertices hold these parts in order of their number, i.e., the lowest-numbered
vertex holds some preﬁx of the input stream, the next-lowest-numbered vertex holds some preﬁx of the rest of the
stream, etc. The reason for this requirement is that we simulate the partial-pass streaming algorithm by moving the
state of the algorithm from one vertex to another in the order that they hold the input. As the degree of vertices in the
communication cluster can be low, we may not have enough bandwidth to distribute information about which part
of the input is held by which vertex; therefore, we need the input to be given in this predetermined manner. In our
applications, it is not diﬃcult to arrange the input so that this condition holds.
